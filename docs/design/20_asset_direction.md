# 美术方向与素材分类规范

任务状态、验收结论和后续排期只维护在 [10_todo.md](10_todo.md)。本文件定义美术口径、内容分类与扩展规则。

## 盘点范围与问题

盘点范围包括仓库中的图片、音频、字体、场景资源引用、物品与怪物配置，以及代码直接绘制的界面。`.godot` 截图、导入缓存、`bin` 和 `obj` 不算交付素材。

盘点时原有美术源文件只有两份：

| 来源 | 用途与问题 | 处理口径 |
| --- | --- | --- |
| `assets/ui/actor_placeholder.svg` | 蓝紫渐变、人像圆角卡片；主角、敌人和全部怪物队列共用，无法辨认物种；与古卷界面配色不协调 | 保留原文件作为历史占位来源；游戏角色使用透明全身形象 |
| 根目录 `icon.svg` | Godot 默认应用图标，不能代表游戏身份 | 游戏应用图标采用自制玉色丹炉图形 |
| 代码绘制的木框、纸面、按钮 | 暖棕、米白、铜金，方向符合 `05_ui_style.md`，不需要整套重做图片 | 保留可缩放的程序化界面样式 |
| 背包文字色块、系统 emoji | 物品只能读名称；书卷、装备、隐私锁依赖系统彩色 emoji，机器间外观可能不同 | 固定 SVG 图标；保留物品名称、数量和详情文字 |
| 字体与声音 | 原仓库没有独立字体、音效或音乐 | 正文使用可随项目分发的中文字体；声音按可选事件设计 |

主要矛盾是正式素材不足，并非已经存在多个完整美术包。避免为了补数量引入不同作者、不同透视和不同像素密度的现成包。

## 统一视觉方向

- **世界观**：温和的东方修仙桌面陪伴；古卷界面与小型像素风角色。界面承担信息，角色承担辨识和陪伴。
- **基础配色**：深暖棕轮廓 `#4A3728`、米白 `#FFF0CF`、玉绿 `#7D9875`、铜金 `#C69B55`。区域色为点缀，不给整张角色图再乘一层区域染色。
- **区域色**：苔洞为灰绿，洞蛛为赭红，影蝠为灰紫，阴潮为蓝玉，菌坑为橄榄绿，幽骨为米白和暗棕。颜色之外还要有轮廓差异。
- **形象**：完整透明全身图、暖棕外轮廓、左上光、较大色块、克制的材质层次。主角朝右，怪物朝左；无卡片、地面、投影或烘焙棋盘背景。
- **Boss**：优先改变头部、腹部、翼形、根肢、骨甲等轮廓，再用铜金装饰标识身份；不能只靠放大和换色。
- **图标**：32 单位网格，48px SVG 文件，28px 背包展示。轮廓比内部花纹优先；同一家族允许共享基础形状，以配色和小饰纹区分内容。
- **可读性**：背包格 64px，名称与数量仍可阅读；角色舞台 80px，常态陪伴 24px。判断标准是实际缩小后的页面，不是源图放大效果。
- **纹理**：小面积纯色优先；纸纹若使用，应极淡，不能穿过正文降低对比度。

PNG 是像素风生成原图，并非经过逐像素校正的固定 96×96 动画帧。制作正式动画前需要统一实际像素网格、脚底基线和帧间轮廓，不能直接将多次生成的图拼成连续动画。

## 素材分类与内容边界

| 类别 | 内容定义 | 文件与规格 | 扩展方式 |
| --- | --- | --- | --- |
| 主角 | 修士基础形象；待机、修炼、攻击、受击、突破、休息状态 | `characters/player`；透明 PNG；状态帧另设目录 | 服装/境界变体沿用参考形象，状态与皮肤分别管理 |
| 怪物 | 配置中的 6 普通怪、5 Boss；以后新增区域物种 | `characters/monsters`；透明全身 PNG | 每种怪物一个稳定 ID；区域家族、普通/Boss、状态分开标记 |
| 原材料 | 草、花、果、矿石、玉、鱼、水、骨、墨、残页等 | `items/materials`；48px SVG | 按来源与用途分族，不能用颜色替代所有物种差异 |
| 种子 | 灵草、灵花、灵果种子 | `items/seeds`；48px SVG | 复用种袋外形，中央植物符号与作物一致 |
| 消耗品 | 丹药、符箓、灵液、刷新令、鱼饵 | `items/consumables`；48px SVG | 容器/载体区分类型，药性通过小面积区域色区分 |
| 灵膳 | 正式四菜谱与旧存档相关食品 | `items/food`；48px SVG | 碗、盘、食材轮廓复用；旧内容保持兼容索引 |
| 阵法 | 阵盘与阵旗 | `items/formations`；48px SVG | 圆/八角阵盘与旗帜区分载体，再设计阵眼 |
| 装备 | 21 模板、7 系列；武器、护具、饰品 | `items/equipment`；48px SVG | 模板共享图；稀有度框、强化数字和词条由 UI 叠加 |
| 界面 | 书卷、背包、锁、灵石、活动、设置、槽位、未知物品 | `ui/icons`；48px SVG；应用图标128px | 保持同一网格、轮廓宽度和留白；禁止重新引入彩色 emoji |
| 区域插画 | 五区域的小型风景题图、地点卡、鱼塘/灵田示意 | `environments/{region}`；横幅与方形地点图分别设计 | 与区域配色绑定；仅在有明确展示入口时制作，常态底栏不用完整风景 |
| 特效 | 攻击、护盾、掉落、突破 | `effects/{event}`；透明帧序列或引擎粒子 | 与主体分层；事件短促，工作模式可抑制表现 |
| 字体 | 正文、数字与标题基础中文字体 | `fonts`；原始 TTF 与原许可证 | 默认用一套字体稳定小字号，书法字只用于较大的非正文装饰 |
| 声音 | 点击、制作、胜利、突破、缺料提示；可选区域环境声 | `audio/sfx` 与 `audio/ambience`；短 WAV / 循环 OGG | 音效以事件命名，默认静默；避免为每件物品复制同一种提示音 |
| 扩展内容 | NPC、成就徽章、新境界、新区域、季节装饰、宣传图 | 分类目录内增加家族，不另建无结构的杂图目录 | 先确定玩法与实际入口，再按同一模板补图 |

锻造、附魔和更高境界属于功能蓝图时，素材不能被误认为功能已经开放。美术文件、运行配置、入口开放状态是三个独立维度。

## 索引、命名与接线

素材权威索引为 `assets/asset_manifest.json`。每条记录包含稳定 `key`、资源 `path`、`category`、可选 `family`、来源方法与提示词 ID。

示例：

```json
{
  "key": "equipment:eq_weapon_qi_outer_moss_blade",
  "path": "res://assets/items/equipment/weapon_short_blade_01_v1.svg",
  "category": "equipment",
  "family": "series_qi_outer_cave",
  "source": { "method": "project_vector", "recipe": "sword", "accent": "jade" }
}
```

- 主角、怪物、物品和界面分别用 `player:`、`monster:`、`item:`、`ui:` 前缀。
- 装备按 `EquipmentTemplateId` 选图，不按随机生成的 `EquipmentId` 选图；旧装备按槽位回退。
- 怪物配置 `visual.portrait` 指向对应 PNG，`tint` 通常为白色。动画速度和幅度保留在配置中，不写进图片。
- `GameArtCatalog` 根据索引查图并缓存纹理。未知物品用统一兜底图，名称仍显示完整业务含义。
- 新文件使用 `_v1` / `_v2` 等版本，替换索引后保留上一版来源。透明主体不预先合成纸面或品质框。
- SVG 和提示音可通过 `python tools/art/build_vector_assets.py` 重建。该命令不调用付费图片服务，不重新生成角色 PNG，也不下载字体。
- 生成提示词保存在 `docs/art/generation_prompts.json`；扩展模板见 `21_asset_prompt_library.md`。
- 双击 `docs/art/asset_gallery.html` 可离线分类、搜索与试听；Godot 原生图鉴为 `scenes/ArtSmokeTest.tscn`。

## 来源与外部素材准入

角色使用内置 imagegen，以主角为风格参考；图标与提示音由项目代码生成。没有将这些自制或生成内容统一宣称为 CC0。

中文字体取自 [Google Fonts 官方 Noto Sans SC 目录](https://github.com/google/fonts/tree/main/ofl/notosanssc)，原始字体与 [OFL 1.1 许可证](https://raw.githubusercontent.com/google/fonts/main/ofl/notosanssc/OFL.txt) 一起保存到 `assets/fonts`。不要删除分发时附带的版权与许可文本。

外部购买/下载应按“单个资产包”评审：记录原始页面、作者、许可证文本、下载日期与哈希；检查透明度、视角、轮廓、材质层次和缩小表现。不直接使用搜索结果预览图、带水印图或授权不明的转载图。现成音效比视觉包更适合独立采购，视觉包应先通过同画面比较。

正式导出时，除图片、字体和 WAV 的导入资源外，还要包含运行读取的 `assets/asset_manifest.json` 以及已有的配置 JSON；外部字体原许可随包保留。导出包验证以 `10_todo.md` 的独立发布任务为准。
