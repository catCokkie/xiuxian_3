# 05 界面风格规范（参考图）

## 总体方向
- 视觉关键词：古卷、木框、暖棕、像素灵宠。
- 布局结构：`底部常驻条 + 中上部可展开主面板`。
- 目标：既有桌宠陪伴感，也有 RPG 面板的系统深度感。

## 分层定义
1. 桌面底栏（常驻）
- 常态高度：96 逻辑像素；实际战斗且主面板关闭时展开至 210 逻辑像素。工作模式保持常态高度。
- 内容分三行：灵宠与活动摘要、境界/活动/副本选择及快捷入口、修炼与探索进度。选择器与进度条使用独立行。
- AP 速率与配置校验等开发信息进入调试层，不挤占常态底栏。
- 交互：支持拖动排序，默认半透明低打扰。

2. 主系统面板（展开）
- 采用“书页/卷轴”形态，顶部页签分为左右两组：
- 左组（游戏内容）：`修炼`、`动态`、`装备`、`背包`、`坊市`、`统计`、`校验`（解锁条件见 `02_systems.md` §21）。
- 右组（功能设置）：`Bug反馈`、`设置`。
- 主内容区只显示一个当前页面；左右两组页签共用唯一选中状态。设置与反馈页隐藏游戏内容。
- 书本宽度不超过 960、高度不超过 720 逻辑像素；按实际逻辑视口收缩，底部预留常驻栏空间。字号缩放后重新计算尺寸和位置。
- 标题、页签与货币栏固定；设置子页独立滚动，长内容不能覆盖固定动作行。
- 左上角提供显式关闭按钮。
- 底部状态条固定显示灵石数量与货币图标。
- 关闭时回到底栏，不销毁状态。
- `动态` 页签延续书页式阅读感，事件列表按"最新在上"排列，单条记录控制在 2-3 行内，避免信息墙。
- 战斗类事件使用轻量状态色区分：胜利偏暖金、失败/撤退偏灰红，但不使用持续闪烁或高频动效。
- Demo 版优先展示真实可用入口；未接线完成的功能入口不在页签层直接暴露。
- `Bug反馈` 页使用实用型布局：上方说明，中间多行输入，下方为复制/导出/打开目录动作行。
- `设置` 页对非正式功能不隐藏语义，而是显式标注 `（预留）` / `（实验）`，避免玩家把 demo 选项误判为正式承诺。

3. 文案管理
- UI 文字统一收口在 `scripts/ui/UiText.cs`。
- 场景中的文本仅作默认值，运行时由控制器从 `UiText` 覆盖。
- 新增文案时优先加到 `UiText`，避免在多个脚本重复硬编码。

## 修炼首页与背包
- 首页顺序为「境界与资源 → 当前活动 → 下一步 → 精通与详细状态」。
- 境界卡提供经验进度、钱包资源、突破条件与突破按钮。
- 活动卡只显示当前模式的配方/地块/鱼塘及相关动作；未解锁模式不显示。副本满探索后提供显式 Boss 挑战入口。
- 下一步说明使用具体动作；详细状态和 11 系统精通默认折叠，可手动展开。
- 背包网格按滚动视口实时重排，首次打开与重新打开保持一致；悬停详情限制在视口内。
- 换装以背包中的具体装备为入口；装备页提供进入背包和强化已穿戴装备的动作。

## 美术与动效约束
- 主色：羊皮纸米黄 + 木质棕 + 铜金点缀。
- 字体：正文 14、页面标题 18 逻辑像素，辅助说明保持可读性。
- 羊皮纸上的正文使用深棕 #4A3728；浅色字 #FFF6E2 放在深棕按钮上。禁用文字用深灰棕，不能使用纸面上的白字。
- 使用 8/12/16/24 的间距层级，卡片统一内边距、圆角与边框。
- 动效：
- 展开面板用“翻页/滑出”0.2-0.3s。
- 底栏灵宠保持低频呼吸与眨眼动画。
- 状态变化（突破/掉落）给短时高亮，不长时间闪烁。

## 可用性约束
- 任何分辨率下底栏不得遮挡任务栏关键区域。
- 面板默认居中，支持记忆上次位置。
- 提供“工作模式”：隐藏面板，仅保留极简底栏。

## 活动模式选择器规范

### 设计目标
- 从 4 模式升级到 11 模式后，扁平下拉列表过长。改用**分组二级菜单**保持低打扰。

### 视觉结构
```
┌────────────────────┐
│ ▼ 当前：炼丹       │  ← 底栏右下常驻入口（单行显示当前模式）
└────────────────────┘
        ↓ 点击展开
┌────────────────────┐
│ 📦 采集            │  ← 分组标题（不可选）
│   副本 · 灵田      │
│   矿脉 · 灵渔      │
│ ⚒ 加工             │
│   炼丹 · 炼器      │
│   符箓 · 烹饪 · 阵法│
│ 🧘 修行            │
│   修炼 · 体修    │
└────────────────────┘
```

### 样式约束
- 分组标题：铜金色小字 + 分隔线，不可点击。
- 可选模式：淡褐色文本，hover 时背景微亮。
- 未解锁模式：默认不显示，避免提前泄露系统规模；仅在开发/预览态下才可使用灰色占位 + 锁图标方案。
- 当前模式：左侧显示金色圆点标记。
- 展开动效：从底栏向上弹出，0.15s 淡入。
- 收起：点击任意模式或点击外部区域。
- 字体与主色沿用羊皮纸米黄 + 木质棕风格。
- 详细交互定义见 `02_systems.md` §21（渐进解锁）和 `15_ui_prompts.md`。

## Toast 通知规范

> **实现状态（2026-04-03）**：Toast MVP 已实装。`scenes/PrototypeRoot.tscn` 已挂载 `scripts/ui/ToastController.cs`，并由 `PrototypeRootController.cs` 接线。当前支持队列式短通知（突破、精通、获得新装备、炼丹完成、强化完成），顶部居中显示、自动淡出，最多同时显示 3 条；下表中的通知分级仍可作为后续细化目标。

### 设计目标
- 桌宠产品以“低打扰”为核心，Toast 必须轻量、短暂、不阻断操作。
- 让玩家在低注意力状态下仍能感知关键里程碑。

### 通知分级（后续扩展目标）
| 级别 | 触发场景 | 持续时间 | 位置 | 样式 |
|------|---------|---------|------|------|
| **重要** | 境界突破成功、Boss 首杀、区域解锁 | 3-4s | 底栏上方居中 | 金色边框 + 微光晕动效 |
| **普通** | 炼丹完成、强化完成、装备掉落 | 2-3s | 底栏上方居中 | 淡褐色背景 |
| **信息** | 丹药自动消耗、日上限命中 | 1.5-2s | 底栏上方居中 | 半透明文本 |

### 规则约束
- 当前实现：同时最多显示 3 条 Toast；超出部分进入队列。
- Toast 不可点击、不可交互，纯展示。
- 当前实现：统一显示在屏幕顶部居中；工作模式下的分级抑制尚未接线。
- 当前动效：停留后淡出（`FadeOutDuration = 0.4s`）；若后续需要更柔和表现，可补淡入。
- UI 文案统一从 `UiText.cs` 提供。
- 当前实现：`scripts/ui/ToastController.cs` 提供 `Enqueue(message, color?)`；若后续扩展分级系统，可再升级为显式 `ShowToast(level, message, durationOverride?)`。

## 修行节律提醒规范（周天系统 UI）

### 设计目标
- 将番茄钟式休息提醒映射为"运功周天"世界观，服务于桌宠挂机场景下的节律感和进度回看。
- 提醒本身必须是可选能力，默认不抢焦点、不暂停游戏、不覆盖主工作流。
- 周天完成时给予微量奖励（悟性/灵石），形成正反馈但不构成经济依赖。

### 提醒强度
| 档位 | 触发形式 | 感知强度 | 适用用户 |
|------|---------|---------|---------|
| `无提醒` | 不主动提示，奖励静默发放 | 无 | 希望完全静默挂机的用户 |
| `弱提醒` | Toast + 底栏高亮"小周天圆满" + 可选未读徽标 | 低 | 默认档，适合大多数桌宠用户 |
| `强提醒` | 居中卡片"小周天·第N轮" + 窗口 attention + 未读徽标 | 中 | 明确希望被提醒休息的用户 |

### 展示结构（周天摘要卡片）
- 标题：`小周天·第 N 轮` / `大周天圆满`，使用修仙世界观命名。
- 奖励行："+3 悟性（周天奖励）"以金色 (#C8A050) 高亮显示。
- 主摘要：展示一个周期内的 `灵气`、`悟性`、`境界经验` 主增量。
- 次摘要：展示当前主行为推进，例如 `探索 +18%`、`完成回气丹 2 批`、`收获灵草 6`。
- 事件角标：用一行小字汇总 `突破 1 / 精通解锁 1 / 装备 2` 等关键事件数。
- 建议文案：调息期 → "运功一周天，建议起身调息片刻"；入定期 → "四周天圆满，可入定休憩"。语气中性，不做命令式文案。

### 样式约束
- `弱提醒` 沿用 Toast 体系的暖棕 + 铜金点缀，控制在 2-3 行内，不做居中遮挡。
- `强提醒` 可在主条上方居中出现更完整卡片，但高度不应超过屏幕高的 18%。
- 任何档位都不得使用持续闪烁、频繁抖动或自动抢焦点。
- 若用户处于 `工作模式`，则 `强提醒` 自动降级为 `弱提醒`。
- 调息期底栏可显示淡金色小图标提示"调息中"，不超过 5 分钟后自动消失。

### 配置建议
- 设置页路径：`设置 → 系统 → 修行节律`。
- 选项：开关、提醒强度（三档）、小周天周期（25/45/60/90 分钟）。
- 默认值：`开启 + 弱提醒 + 25 分钟`。

## 美术素材与字体

- 素材分类、命名、来源及扩展要求统一遵循 `20_asset_direction.md`；可复用提示词见 `21_asset_prompt_library.md`。
- 正文使用项目内 Noto Sans SC，以 `ui_sans_sc_regular.tres` 固定为400字重；标题通过字号建立层级，避免小字号书法字体。
- 主角和怪物使用透明像素风全身图；舞台显示80px、常态陪伴24px；不得由原图尺寸撑大控件。
- 背包使用48px源SVG、28px显示图标；名称与数量保留。书卷、隐私锁及活动图标使用同一暖棕轮廓图标族。
- 物品类别与装备品质采用浅色格底，深棕正文；程序绘制品质框/强化数字，不把这些信息合成进物品原图。

## 操作深化的渐进呈现

规格采用`02_systems.md`§24，路线采用`22_play_routes.md`；本节是扩展交互设计，实施状态只见`10_todo.md`。

- 修炼概况顶部显示唯一主目标：名称、当前进度、一个主要缺口、推荐入口和“换个方式”。可选支线最多两项，默认折叠，取消追踪不损失资源。
- 当前活动操作卡按“目的→做法→投入→结果→停止规则”组织。基础做法默认选中，进阶做法只在实际解锁后出现；不能一开始铺出28个操作按钮。
- 解锁预告只显示下一条与当前目标相关的内容，以及清楚的前置；未开放功能不显示可执行按钮。
- 目标跳转只打开相关活动/配方，不立即消费或改变装备。选批次/库存保留后预览材料与预计缺口，玩家确认才开始。
- 配方提供一个确定性/可预算来源入口；“材料不足”必须具体写物品及缺口，不能只显示红色失败。
- 装备比较同时展示当前与继承后差值，分解逐项预览回收材料。锁定、保留与来源不明提示使用文字配图标，不能仅靠颜色。
- 挑战页列敌人已知威胁、备战预设、可能消耗上限、替代方案。战中不出现必须及时点击的技能按钮。
- 路线完成进入书卷内回看页，工作模式只增加静默标记，用户自行展开；不抢焦点、不自动播音、不固定每日红点。
- 常态96px底栏只保留当前活动及目标摘要，不为了新系统常驻扩大。长说明放书卷，新增卡片参与既有滚动与窗口缩放验收。
