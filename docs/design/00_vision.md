# 00 愿景

## 产品定位
- 类型：桌面底部驻留的修仙桌宠挂机游戏 + 轻策略养成。
- 核心驱动：读取用户真实键盘/鼠标操作次数作为修炼进度。
- 引擎与语言：Godot 4 + C#。
- 运行形态：常驻后台，用户工作学习时自然积累进度，并在短时回看时做资源与模式分配。

## 核心体验
1. 做事即修仙：用户在日常打字、点击中持续成长。
2. 低打扰陪伴：桌宠在桌面底部活动，不遮挡主工作区。
3. 明确可控：进度规则透明，玩家能通过主行为切换与资源分配做轻策略决策。
4. 低注意力回看：用户不需要持续盯屏，也能在回看时快速理解“这一轮发生了什么、接下来该做什么”。

## V1 范围
- 包含：
- 全局键鼠计数与活动点转换。
- 境界成长与突破。
- 桌面底栏展示 + 书卷式系统面板。
- 轻量探索遭遇与按输入推进的战斗回合。
- 11 个活动模式组成的基础资源蛛网（采集 4 + 加工 5 + 修行 2）。
- 动态回看（含战斗/制作/突破等全事件流）、节律提醒（周天系统）等低注意力反馈能力。
- 装备、背包、基础加工与常驻增益的最小养成闭环。
- 本地存档、基础防刷护栏与统一存档恢复。
- `Bug反馈` 最小闭环（问题描述、复制日志路径、导出反馈文件、打开数据目录）。
- 不包含：
- 联网排行/社交。
- 复杂技能战斗、多层状态异常、大地图探索。
- 账号云同步。
- V2 预留：短时维护玩法。
- 完整装备内容池、随机词条、套装养成和高深度 build 构筑。

## 产品结构与进度查询

- 主条与图书子菜单服务于低打扰挂机、短时管理两种状态。
- 11系统资源蛛网采用确定性小突破与悟性横向精通；基础规则见`02_systems.md`。
- 设计需让玩家理解目标、看见操作取舍和成长反馈；实施与验证状态只见`10_todo.md`。

## 隐私与合规原则
- 只统计事件数量与频率，不记录按键内容或屏幕信息。
- 不上传任何数据，所有数据仅存储在本地。无网络通信。
- 设置页提供"隐私与采集"子页：一键暂停采集开关 + 本次会话采集计数 + 隐私声明全文。
- 首次启动弹出隐私说明卡片（3 句话 + "了解"按钮），仅展示一次。
- 详见 `15_ui_prompts.md` §13（设置—隐私）和 §14（首启卡片）。

## V1 目标指标
- D1 留存 >= 40%。
- 首个使用时段能理解输入映射并体验一次准备/制作；首次突破及后续境界耗时按有效输入/AP分布校准，不把固定60–90分钟到第3境视为既定承诺。
- 70% 用户能理解“输入行为 -> 修炼收益”的映射关系。

## 内容深化的体验目标

- 五区域组成有收束的炼气篇章，路线规格见`22_play_routes.md`。
- 11种活动各有可解释的操作取舍；主线与三准备支线可自由切换，首次通关不要求全系统精通。
- 一次30–90秒管理能确定一个目标、一个缺口与一种解决方式；长期离开不产生任务债务。
- 基础来源支持确定性准备，稀有物用于横向收藏与进阶替代。扩展规则见`02_systems.md`§24；实施状态只见`10_todo.md`。
