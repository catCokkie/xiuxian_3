# 生产控制之后的设计复核

日期：2026-10-13。参数以02号为准，任务状态只见10号。本文区分源码事实、现有模型证据与需要试玩的假设；建议不等于扩大实施范围。

本页为提出建议时的证据快照，不能作为后续版本的运行规则；当前生产、准备与终点契约查02§24.2/24.11，实施与验证记录只查10号。

## 1. P1：玩家能指定轮数，却还难判断该做多少

源码事实：生产面板能显示已完成轮数、基础产量和缺料状态，但`BookTabsController.Layout.BuildHomeNextStep`仍主要按活动给固定操作说明；`GuideState`只有首次输入、遇敌、胜利、开书四种提示。它们没有根据当前库存、Boss威胁和已选配方解释准备缺口。

影响：玩家可能从无限加工转向随意填10轮，仍不知道准备是否足够。缺料摘要没有指明缺哪种材料、差多少、在哪里取得；“可开始”也不能代表“这份投入对当前目标有用”。

建议：先增加一个轻量可选目标，如“准备下一次挑战”。按已有库存给出1–2种准备建议，明确需要的批数、每轮实际产出、材料缺口和来源入口；最终批数由玩家编辑。战斗收益可以显示属性差值或估计回合变化，标明估算，不能承诺必胜。有限轮数、长期库存目标和材料保留量分别表达，避免一张表混淆。

验收证据：空库存、已有半份补给、产量加成、材料不足和已满足目标五种状态，建议不会要求重复造永久工具，不自动购买或占用另一活动。

## 2. P1：切换项目的进度损失与可中断办公体验冲突

源码事实：`AlchemyState.SelectRecipe`、`RecipeProgressState.SelectRecipe`、`FormationState.SelectRecipe`、`SmithingState.SelectTarget`切换不同项目会清零当前进度并重置计划；停止、继续及同项目重复选择则保留。当前界面通过选项提示说明这个边界，但没有各配方的暂停记录。

影响：临时改做克制物、比较另一配方或换装备，会损失之前积累的制作输入。轮数控制解决了完成后的停止，却没有解决制作中途换目标的成本。

建议：每系统保留各项目的未完成进度和计划，仍只推进当前项目，切换时冻结原项目。炼器记录绑定装备实例并重新检查强化等级/上限；不要让旧低阶完成预算直接兑换成高阶强化。主动清除计划应是独立动作，不因查看选项清除。记录规模按现有配方与合法实例约束，旧档只有当前项目时自然迁入。

验收证据：A做一半→B做一轮→回A→读档/离线，不重复扣费、不多发产物，已完成计划不复活。

## 3. P1：实际突破节奏仍可能跳过渐进教学

源码事实：活动在realm1–5按五波解锁；经验溢出保留，realm9之前的小境界没有区域首通门槛。26号模型却按各区realm3/4/6/8/9主动保持境界。

证据边界：27号“首Boss附近可能已到realm5”是相同输入量的公式反事实，不是实际尽早突破模拟；更早升级会改变战斗时长、制作需求和总经验，不能把原输入量直接当新路线结果。

建议：比较经验够即突破、挑战前突破、离线后集中突破三种真实策略，再与阅读/打字/绘图的在线与离线轨迹组合。教学按当前问题与实际做过的操作触发，未用系统保持折叠；目标指向一个缺口，不同时要求体验11种活动。保留越级准备自由，不用区域硬锁修补教学失效。

验收证据：第一Boss前系统暴露数、阶段成果出现时间、每次回看需要的决定、资源与制作计划变化；以同一周墙钟比较，而非只比输入总数。

## 4. P1：支线收益需要在当前恢复规则下重新证明

模型证据：26号连续HP模型中，最低主线27个模型动作、丹膳42个，丹膳省22灵石，灵气消费为235对90。该模型包含02§24的扩展规格，不能当作已接通的支线试玩；模型动作不是实测点击或回看次数。

源码事实：脱战自然恢复使普通损耗可自行恢复；已有丹膳主要提供通用资源增益、额外产量或战斗防御/回血。抑生丹与镇灵符仍只见扩展规格/模型，运行配方列表没有对应制作入口。

影响假设：低输入玩家在遭遇间已经恢复时，补给管理的收益可能更小。回血型敌人的对策有规则窗口，但玩家尚不能通过两条准备路线取得对应工具；过量生产普通恢复药不能代替战术选择。

建议：先完整接通一种威胁及两种替代准备方案，验证纯基础装备也有合理挑战余量。分别测试主要靠灵田和混合掉落的第二轮供应，把支线价值落在稳定库存、确定装备提升或可见的战术结果。测真实回看频率与准备时间，避免把多管理步骤当作深度。

## 5. P1：通用资源和通用最优升级压低路线差异

模型证据：26号已指出悟性收入远高于推荐组合85/95/145的投入。27号旧模型余额只能作历史快照，不能直接复用为本版精确经济结论。源码中修炼Lv4仍减少全局经验需求8%。

影响假设：如果悟性几乎不缺，增加悟性收益的汤与侧重就很少改变决定；全局经验减免可能成为所有路线共同的第一选择。当前模型没有充分比较该购买策略。

建议：按五个阶段列收入、必要消费、可选投资和余额，对比买/不买通用经验升级的实际结果。让每种侧重对应一个能被观察到的需求，提供明确成果的一次性投入；经济调整需要与支线目的同时校准。不要仅用统一涨价或增加新货币掩盖用途不足。

## 6. P1：生产有限，灵膳使用却默认无限续用

源码事实：`CookingState.AdvanceMeal`与`MealRules.Advance`在有效时长耗尽后自动从库存续用，现有用餐入口没有续用开关或份数预算。持续时间按活跃秒扣减，并非只在战斗中扣减。

影响：玩家指定生产3轮不等于指定使用3份。为某次Boss准备的战斗餐可能在之后采集、制作中耗时并续用，与“安排一段工作所需补给”的心智不一致。是否频繁浪费需要真人轨迹验证，但自动续用的行为由源码确认。

建议：用餐独立提供“只用一份 / 最多续用N份 / 一直续用”，保留旧档当前效果与剩余时长；战斗餐可增加明确的挑战准备场景，不在战斗开始时强制维护。先保持一份基础默认，持续补给由玩家选择。

验收证据：活动切换、时间跨多个持续周期、库存不足、读档和工作模式下，份数预算与实际扣物一致。

## 7. P1：筑基初成之后仍缺少内容收束

源码事实：`RealmBreakthroughRules.CanCrossRealm`仅检查realm9→10是否首通第五区；realm10之后继续返回允许突破，而02§24.11以realm10为本篇终点。

建议：明确本篇完成反馈、纪念与可选收藏；下一境界是否开放由实际内容配置决定。若暂不开放，要说明经验溢出如何保留，尊重已超出境界的旧存档，不回退已有成果。让下一次回看有可选目标，避免只显示没有内容承接的境界数字。

## 下一轮的建议组合

先把“下一次挑战的准备缺口”与“切方保留进度”合成一条完整可中断流程，同时给本篇设置明确收束。随后接通一组战术准备，复测支线与经济；真实突破及一周混合轨迹贯穿验证。新增素材应跟随确认后的实际产物，避免先扩大配方数量。
